# Browser Task — 用浏览器干活

## 核心循环

**看 → 想 → 做 → 再看**。每做一次动作，页面就变了，旧的元素编号全部作废。

```
1. browser_open(url)           打开页面
2. browser_snapshot()          看当前有什么（拿到带编号的元素列表）
3. 从快照里挑出你要操作的那个编号
4. browser_click(ref) 或 browser_type(ref, text)
5. 回到第 2 步重新看         ← 这一步绝不能省
```

**最容易犯的错**：连着点两下，第二下用的还是上一次快照的编号。页面一变编号就错位了，你会点到完全不相干的东西上。

## 操作要点

- **优先用文字定位**。快照里写着"登录"的按钮，比 "div > div:nth-child(3)" 稳得多。页面改版了前者还能用。
- **页面没加载完就操作会失败**。点了没反应先重新 snapshot 看看，别急着重点。
- **输入框要先点再输**。有些输入框不聚焦就输不进去。
- **滚动用 `browser_scroll(direction)`**，direction 是 up / down / top / bottom。要找的东西不在快照里，往往是在下面没加载出来。滚完要重新 snapshot 拿新的编号。
- **跨域 iframe 里的东西，快照里看不到、也点不到**。登录框、支付框、人机验证常常就在这种框里。快照里没有它不是你找错了——撞上就停下来找用户。

## 硬规矩

**下面这些动作执行前必须先问用户，得到明确同意再动：**

- 提交任何表单（尤其是注册、下单、发帖、发消息）
- 付款、订阅、购买
- 删除任何东西
- 授权、授权登录、同意条款
- 涉及到用户真实身份的输入（身份证、银行卡、手机号）

**下面这些不用问**：打开页面、往下翻、点链接看内容、搜索、截图。这些都是只读的。

## 遇到卡壳怎么办

- **要登录**：这里用的是**临时开出来的干净浏览器，什么登录态都没有**——不是用户平时那个浏览器，所以不会"本来就登着"。撞上登录页就停下来告诉用户，**不要自己注册账号，也不要猜密码**。
- **有验证码**：停下来，把情况告诉用户（能截图就把截图给他），请他自己过一下。搜索引擎、购物站对**没有任何 cookie 的全新浏览器**特别容易弹验证（实测百度会弹滑块），这不是你操作错了，是它在防机器人。
- **点了没反应**：重新 snapshot 看看页面到底变成什么样了，通常是弹了个框或者跳转了。
- **截图报错说这个平台截不了**：那是手机端（那边没有截图接口）。别重试，改用 browser_snapshot 把页面结构读出来告诉用户。
- **打开 http 站被挡住**：手机上的安卓不允许开明文网页，会明确告诉你。这条路走不通就改用 http_fetch 抓它的内容——那个能读 http，只是不能在上面点。
- **连续三次失败**：停下来，把当前快照和你的判断告诉用户，问怎么办。别一直重试。

## 收尾

任务完成后说清楚：做了什么、现在什么状态、结果在哪。如果中途跳过了哪一步或者没成功，明说。
