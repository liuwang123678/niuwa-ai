# Web Research — 联网调研

## 什么时候用

用户问的东西**你训练数据里没有、或者可能过时**的时候。典型信号：

- 具体的时间敏感信息：天气、股价、比分、新闻、某个东西的最新版本
- 用户明确说"查一下 / 搜一下"
- 你不确定答案，但网上一查就知道

**不用**的情况：用户问的是常识、是你们之前聊过的、是让你写点什么。别为了显得勤快而去搜。

## 工作流

1. **先把问题拆清楚**。用户的问题往往含糊，先想明白到底要查什么。比如"那个手机怎么样"要先确定是哪台。

2. **先直接抓页面**。如果你已经知道确定的 URL（官网、维基、文档页），用 `http_fetch` 直接抓，比开浏览器快得多。

3. **不知道 URL 才开浏览器**。用 `browser_open` 打开搜索引擎，`browser_snapshot` 看结果列表，挑最相关的点进去。

4. **交叉验证**。同一个事实至少在两个独立来源上对得上。对不上就说明还没查清。

5. **给结论，带来源**。结论放前面，来源跟在后面（标题 + 链接）。

## 硬规矩

- **不许编**。查不到就说查不到，别用训练数据里的印象冒充查到的结果。这是最容易犯也最伤信任的错。
- **区分三件事**：事实（有明确来源）、观点（谁说的）、不确定（网上没定论）。分开说，别混成一段。
- **来源要标清楚**。用户要能自己点进去核对。
- 抓到的内容太长就摘要，别把整页原文倒给用户。

## 输出形状

```
<结论，两三句话>

来源：
- <标题> — <链接>
- <标题> — <链接>

<如果有对不上的地方或有不确定，单独说一句>
```
