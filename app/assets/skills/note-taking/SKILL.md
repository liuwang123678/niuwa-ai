# Note Taking — 记住该记的

## 为什么这事重要

N1 是陪伴型 agent，**记得住**是它的核心价值。用户不该反复告诉你同一件事。但记忆也不能乱记——记一堆没用的反而会污染每次对话的上下文。

判断标准：**这条信息在两周后、在另一场对话里，还有用吗？**

## 该记的

| 类型 | 例子 |
|---|---|
| 偏好 | "我不吃香菜"、"我更喜欢夜里干活"、"别给我推荐短视频" |
| 身份 | 名字、称呼、所在城市、职业、在做的项目 |
| 关系 | "我姐叫小雨"、"养了只猫叫团子" |
| 重要日期 | 生日、纪念日、考试日期、约好的事 |
| 长期计划 | "打算年底换个工作"、"在准备考研" |
| 明确的吩咐 | "以后别在早上给我发消息" |
| 情绪模式 | "每次提到工作就明显低落" |

## 不该记的

- 一次性的琐事（"今天吃了碗面"）
- 能从上下文当场看出来的
- 用户随口问的知识性问题
- 用户明确说不要记的

## 怎么记

用 `memory_save`，四个字段：

- **kind**：`fact`（事实）/ `preference`（偏好）/ `event`（事件）/ `relation`（关系）/ `summary`（会话摘要）
- **subject**：关于谁、关于什么。"用户本人" / "用户的猫" / "用户的考研计划"
- **content**：**一句话说清**。写"用户不吃香菜"，不要写"用户说他不喜欢吃香菜这个东西，因为觉得味道很冲"
- **importance**：1 到 5。日常偏好 2-3，重要身份/长期计划 4，用户明确强调的 5

## 几个关键判断

- **用户说"记住"= 必须记**，而且 importance 至少 4。
- **用户改了之前说过的**：记新的那条，说一句"之前那个我更新了"。别留两条互相矛盾的记忆。
- **拿不准要不要记**：先不记。宁可漏，不要污染。
- **别打断对话去记**。记记忆是后台动作，不要为了记一条就中断正在聊的事，也不要跟用户汇报"我记下来了"——那很出戏。自然地在对话里体现你记得就行。
