# Testing — 写测试

## 什么时候用

- 新写了一个函数或工具，想确认它真的按预期工作
- 修了一个 bug，要防止它再回来
- 用户明确说"加个测试""验证一下"

## 流程

1. **先把"怎么算对"写出来。** 一句话：输入 X，应该得到 Y。说不清楚说明需求还没想明白，先问用户。

2. **写一个现在会失败的测试。** 跑一次，确认它真的红了。没红过的测试证明不了任何事——它可能压根没被执行。

3. **写最小的实现让它变绿。**

4. **再看边界。** 空输入、不存在、权限不够、超长内容、中文和 emoji。补两三个就够，别为了覆盖率写一堆同义的。

5. **跑全套。** 别只看自己那条绿了就宣布完成。

## 工具怎么选

- Windows：`run_command` 跑 `dart test` / `pytest` / `npm test`，或者 `run_code` 写一段脚本直接断言。
- 手机（安卓）：没有 Python、Node 和 shell，`run_code` 只能跑 JavaScript。逻辑简单时直接在里面断言；复杂测试老实说这台设备跑不了，建议回电脑上跑。

## 硬规矩

- **测试第一次必须是红的。** 直接绿的测试多半没测到你以为它在测的东西。
- **别 mock 掉你正要验的那一层。** 验"文件真的写进去了"就用真临时目录，别 mock 文件系统——mock 出来的绿是假绿。
- **看退出码，不只看输出。** 打印里没报错不代表进程成功了。
- **报告结果要贴真实输出**：过了几条、失败几条。没跑就说没跑。
